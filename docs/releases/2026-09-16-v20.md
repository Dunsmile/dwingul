# v20 — 모험 설정을 먼저 확인하고 터치로 계속 조작하기

타이핑 마스터 제목 화면에서 ‘모험 시작하기’를 누르면 기존 게임 화면 안의 ‘모험 설정’ 패널을 연다. 문장 모드와 시작 스테이지를 확인하고 패널 하단 시작 버튼을 눌러야 실제 플레이 요청을 만든다. 돌아왔다가 다시 들어와도 선택값은 유지한다. 같은 화면으로 가던 별도 설정 메뉴는 제거해 메뉴의 중복을 줄였다.

멀리 뛰기의 캔버스와 조작 버튼에는 `-webkit-user-select: none`, `user-select: none`, `-webkit-touch-callout: none`, `touch-action: none`을 명시했다. 현재 점프 렌더러는 해당 영역의 `selectstart`와 `contextmenu` 기본 동작도 취소한다. 설명/푸터/타이핑 입력창에는 적용하지 않으며 점프·급강하·길게 숙이기·여러 손가락 입력·일시정지는 유지한다. 물리·점수·랭킹 규칙은 v19 그대로다. 패키지0.19.1.

## 확인 근거와 한계

- 변경 전 주 메뉴 시작으로 설정 패널이 나타나지 않는 실패 재현. WebKit에서 버튼의 선택 정책이 `auto`/`text`, 선택·문맥 메뉴 이벤트가 취소되지 않는 상태 확인.
- 신규 Chromium/WebKit320·390·1440px6개 화면: 설정 전 플레이 생성0회, 설정 확인 후1회, 긴 모드×2, 선택값 유지, 가로 넘침 없음. 선택 방지 정책/선택·문맥 메뉴 이벤트 취소/1.4초 숙이기/급강하/다른 손가락 해제/일시정지/외부 영역의 기본 동작 검증 통과.
- 기존 타이핑 메뉴·상점·장비·캐릭터·프로필·11스테이지 긴 모드 전투12개 화면 회귀 검사 통과.
- 전체297개 단위·API 검사, 배포 CSS 생성, 정적30페이지 빌드, 구문 검사 통과. 공식 게임 클라이언트로 점프·2단·급강하와 캔버스를 추가 확인했다.
- Apple의 [Safari CSS 공식 참조](https://developer.apple.com/library/archive/documentation/AppleApplications/Reference/SafariCSSRef/Articles/StandardCSSProperties.html)는 선택 방지와 iOS 전용 길게 누르기 메뉴 방지 속성을 설명한다. Playwright WebKit 모바일 에뮬레이션은 데스크톱 WebKit을 사용하므로 iOS 전용 기본 팝업 자체를 재현하지 못한다. 실제 아이폰 또는 iOS 시뮬레이터는 사용 가능한 환경에 없어 네이티브 번역 메뉴의 실기기 확인은 수행하지 못했다. 자동 검증 통과를 실기기 검증으로 표현하지 않는다.
- 모든 플레이/프로필 검사에는 격리 메모리DB를 사용했다. 근거 output/v20/browser.json, output/v20/typing-menu-regression.log, output/v20/tests.log, output/v20/official-client/.
