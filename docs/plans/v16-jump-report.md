# v16 멀리 뛰기 구현 보고서

## 구현 범위

- 현재 점프 런타임의 기본 규칙을 `v16`으로 올렸다. 시작 체력은 3이며 충돌마다 1 감소하고 0에서 기존 착지 종료 연출로 들어간다.
- 하트는 첫 900~1100m 사이에 등장하고 이후 900~1100m 간격으로 반복된다. 획득하면 체력 1을 회복하며 최대 3을 넘지 않는다.
- 하트 예정 거리에 도달해도 현재 패턴의 예약 장애물이나 앞쪽 장애물이 남아 있으면 기다린다. 모든 장애물이 지나간 뒤 하트를 내보내고, 하트가 주자에게 도착하는 거리와 360px 여유 구간 동안 다음 패턴 생성을 유예해 회복 아이템과 장애물이 겹치지 않는다.
- 거리를 기준으로 1000m마다 쉬움, 조금 쉬움, 보통, 어려움, 전문가, 마스터의 6단계가 열린다. 마지막 단계는 5000m 이후 유지된다.
- 단계가 바뀔 때 장애물 목표 빈도는 직전 단계의 1.2배가 된다. 기존 v13의 10초마다 속도 +24와 목표 밀도 +1 규칙도 함께 적용한다. 모든 패턴은 기존 장애물 종류별 최소 안전 간격을 계속 지킨다.
- 단계별 배경과 네 장애물 계열을 `jump-stage-{2..6}` 및 `jump-stage-{2..6}-{short|wide|double|slide}` 이름으로 연결했다. 첫 단계는 기존 숲 자산을 쓴다. 현재 단계에서 다음 단계만 미리 데워 장거리 시작 시 대형 배경을 한꺼번에 읽지 않는다. 자산이 아직 없거나 로딩 중이면 단계별 색상 배경과 기존 장애물 도형이 보인다.
- 2~6단계의 지면은 `jump-stage-{2..6}-ground`를 별도로 타일링한다. 첫 단계는 기존 `jump-ground`를 유지한다.
- 패턴 덱 100개는 그대로 보존하되 단계별 가중 선택을 적용한다. 쉬움은 기본 75%와 넓은 장애물 25%, 조금 쉬움에서 2단 장애물, 보통에서 숙이기 장애물이 등장한다. 이후 단계는 2단과 숙이기의 비중이 높아진다.
- 상단 상태 문구는 v16에서 빈 문자열로 유지하고 캔버스 안에 거리, 체력, 단계만 표시한다. 공통 일시정지 버튼은 유지한다.

## 입력 누락 원인과 수정

기존 구현은 첫 점프와 2단 점프를 모두 사용한 상태에서 착지 직전에 들어온 입력을 즉시 거절했다. 다음 프레임에 착지해도 거절된 입력을 기억하지 않아 사용자가 키가 씹혔다고 느끼는 경계가 있었다. 또한 반복 키다운 판정은 브라우저의 `event.repeat`에만 의존했다.

v16은 거절된 점프를 150ms 보관하고 그 안에 착지하면 즉시 다음 점프로 소비한다. Space, ↑, W를 명시적인 눌림 집합으로 관리해 브라우저 반복 이벤트 차이에 영향을 덜 받는다. 키를 놓거나 창 포커스를 잃거나 일시정지에 들어가면 눌림과 버퍼를 모두 비운다. 포인터 숙이기는 기존 pointer capture 및 문서 수준 release 처리를 유지한다.

## 공유 파일 통합 필요 사항

루트 담당자가 아래 연결을 해야 현재 기본 경로에서 v16이 선택되고 과거 기록이 보존된다.

1. 변경 전 `public/js/jump-game.js`와 `public/js/jump-patterns.js`를 각각 `public/js/legacy/jump-game-v13.js`, `public/js/legacy/jump-patterns-v13.js`로 보관한다. legacy 게임 모듈의 패턴 import도 `./jump-patterns-v13.js`로 바꾼다.
2. `public/js/games.js`에서 현재 `jump-game.js`를 v16 creator로 가져오고, legacy v13 creator를 별도 import한다. `normalized.version === 'v13'`은 legacy v13, 기본 또는 `v16`은 현재 v16으로 라우팅한다.
3. `public/js/game-options.js`의 기본 점프 버전과 모드를 v16으로 올리고 `jump-distance-v16` 표시 이름을 추가한다. v13 설정과 기록 mode는 그대로 해석한다.
4. `public/js/scene-art.js`의 `SCENE_ART_SOURCES`에 `jump-stage-2.png`부터 `jump-stage-6.png`, 각 단계의 short/wide/double/slide 20개 경로를 등록한다. 현재 런타임이 사용하는 정확한 키는 위 구현 범위에 적었다.
5. 공통 CSS에서 `.dg-game--jump-v16 .dg-game__status { display:none; }`와 툴바가 일시정지 버튼 너비로 정렬되는 규칙을 추가한다. `.dg-game__pause`는 숨기지 않는다.
6. 공유 asset preload 목록은 첫 단계 자산만 초기 gate에 두고, 나머지는 런타임의 `warmStage`가 요청하도록 둔다.

## 자동 검사 증거

`node --test tests/v16-jump.test.mjs tests/jump-v4.test.mjs tests/jump-rhythm-v11.test.mjs` 결과 21/21 통과했다. 검사 범위는 6단계 경계와 1.2배 목표 빈도, 단계별 120초 실제 스케줄 빈도의 단조 증가와 안전 clamp, 최고 속도 420px/s에서 100개 주 장애물의 실제 회피 가능 입력 탐색, 초반 단순 패턴 및 단계별 동작 해금, 기존 10초 속도/밀도 증가, 100개 패턴의 종류별 안전 간격, 3회 체력과 최대 3 회복, 900~1100m 하트 간격, 장애물이 없는 하트 통로, 입력 버퍼/키 눌림/일시정지 정리 코드, 기존 단일·2단·숙이기 물리 회피, v11 거리 스케줄 회귀다.

공유 v16 라우팅이 합쳐진 뒤 `DW_TEST_URL=http://localhost:4182 node tests/v16-jump-browser.mjs`도 통과했다. 실제 Chromium에서 Space/↑/W와 착지 버퍼, 일시정지 시간·물리 동결, 자동 회피로 6000m와 여섯 단계 방문, 하트 획득 후 최대 체력 3 유지, 세 번째 충돌 뒤 ending, ending 도중 일시정지, 재개 후 착지 결과까지 확인했다. 콘솔 page error는 없었다.

최종 stage PNG와 scene registry가 합쳐진 뒤 같은 검사를 다시 통과했다. `/tmp/dwingul-v16-jump/stage-2.png`부터 `stage-6.png`, `heart-corridor.png`를 원본 크기로 직접 열었다. 숲·버섯 계곡·유적·수정 동굴·설산 배경과 각 지면이 서로 구분되고, 짧은 통나무/버섯·천장 기둥/종유석·수정 장애물이 지면 또는 천장 접점에 맞았다. 숙이기 장애물 아래 통과 공간과 자동 입력 생존을 함께 확인했다. 하트는 첫 단계의 빈 지면 오른쪽에 장애물 없이 단독 표시됐고 이후 획득됐다.

기존 `jump-v13-tuning.test.mjs`의 현재 모듈 기본값 단언은 공유 라우팅과 legacy v13 보관 전에는 의도대로 실패한다. 루트 통합 뒤 이 검사는 legacy v13 파일을 확인하도록 갱신해야 한다. 실제 앱 브라우저 검사는 공유 라우팅과 새 scene source 등록 후 수행해야 v16 화면을 검증한다.

## 남은 통합 QA

- 실제 런타임 하트는 최대 체력 상태 획득과 상한 3을 확인했다. 체력 2에서 획득해 3으로 바뀌는 수치 변화는 순수 규칙 검사로 확인했으므로, 최종 화면 QA에서 의도적으로 1회 충돌 후 첫 하트까지 생존하는 시나리오를 추가하면 시각 증거도 완성된다.
