# v11 도심 질주 인계

## 구현 결과

현재 도심 질주는 `v7` 규칙으로 시작한다. `public/js/legacy/city-engine-v6.js`는 변경 전 v6 엔진을 보존하며, 차고 정산은 저장된 `v4`·`v5`·`v6`·`v7`에 맞는 엔진으로 재현한다. 기존 `basic`, `sport`, `touring` 소유 정보와 능력치의 속도·연료 값은 유지된다.

연료는 주행 시간과 충돌을 함께 버티는 체력이다. 자연 감소량은 초당 0.5이고 연료 아이템은 15를 회복한다. 기본 충돌 피해는 10이며 차량 방어만큼 줄어든다. 실제 차체가 새로 겹치는 순간에만 한 번 피해를 주고, 그 뒤 0.9초 동안 다른 충돌 피해를 막는다. 엔진은 현재 겹친 차량 ID를 `contactIds`에 보관하므로 보호 시간 중 시작된 겹침이 끝나기 전 뒤늦게 피해를 주지 않는다. 연료가 0이 된 경우에만 `reason: "fuel"`로 끝난다.

동전과 연료 배치 간격은 v6의 2/3가 되어 밀도가 각각 1.5배다.

| 배치 | v6 거리 간격 | v7 거리 간격 |
| --- | ---: | ---: |
| 첫 동전 | 150–220m | 100–146.67m |
| 다음 동전 | 150–230m | 100–153.33m |
| 첫 연료 | 140–180m | 93.33–120m |
| 다음 연료 | 550–700m | 366.67–466.67m |

동전을 주울 때 차량별 `boostProc` 확률로 부스터가 1칸 충전된다. 이 판정도 주행의 seeded random을 사용하므로 클라이언트와 서버 재현 결과가 같다. 부스터는 10칸을 채워 시작하고 차량별 `boostDuration` 동안 지속된다.

## 원화 경로와 투영

플레이어 원화의 안정 경로는 `/assets/pixel/illustrated/vehicles/{id}.png`이고 교통 차량은 `/assets/pixel/illustrated/traffic/{car|van|truck|bus}.png`이다. 모두 투명 정사각 PNG를 전제로 한다. 차량은 후방 3/4 직립 시점이며 바퀴 접점이 이미지 높이의 약 88%에 오도록 제작한다.

`vehicleSpriteBox()`는 물리 footprint의 가까운 모서리를 `floorY`로 정하고 원화의 88% 지점을 그 위치에 맞춘다. 따라서 원화를 도로 사각형으로 찌그러뜨리지 않으면서 그림 아래의 footprint가 실제 차체 길이와 통과 판정을 보여준다. 원화가 없거나 아직 로드되지 않았을 때는 같은 box와 접점을 쓰는 직립 기하학 차량을 그린다. 이용자가 제공한 Newdaily와 Naver 자료는 5차선 및 후방 시점의 일반적인 가독성만 참고했고 화면 구성이나 자산은 복제하지 않았다.

## 메인 통합 필요 사항

다음은 이 작업의 소유 범위 밖이라 메인 작업에서 반영해야 한다.

1. `public/js/app.js`의 차고 이전·다음 계산 `(current + (next ? 1 : cityCars.length - 1)) % cityCars.length`로 바꾼다. 현재 `+3`과 `%4`는 8종 중 뒤의 네 종을 순환하지 못한다.
2. `public/js/catalog.js`의 `currentGameModes.racing`을 `city-basic-v7`로 바꾼다. 그래야 기록 등록 검증과 기본 랭킹이 새 규칙을 가리킨다.
3. 같은 파일의 도심 질주 규칙에서 `초당 2칸`, 모든 차 `50토큰` 문구를 지운다. 초당 0.5, 충돌 피해와 0.9초 보호, 차량별 가격을 안내한다.
4. 새 시작을 허용하는 서버 공통 버전 목록이 따로 있다면 `v7`을 추가한다. 차고 정산 자체는 이미 네 엔진 버전을 분기한다.
5. v6 고정 총계를 확인하는 브라우저 fixture는 새 v7 seeded fixture로 대체하거나 v7의 피해·보호·회복 가능성 불변 조건을 확인한다. v6 단위 회귀는 `tests/city-v6.test.mjs`가 legacy 엔진을 직접 사용한다.
6. 완성된 차량 및 교통 PNG를 위 안정 경로에 둔다. 자산이 없어도 게임은 기하학 폴백으로 동작한다.

`gameSettings()`는 저장된 이전 실행을 재현할 수 있도록 도심 질주 `v4`·`v5`·`v6`, 리듬 `v7`·`v9`, 멀리 뛰기 `v4`·`v5`·`v6`을 명시적으로 받으면 그대로 보존한다. 버전이 없거나 알 수 없는 값이면 도심 질주 `v7`, 리듬과 멀리 뛰기 `v11`을 선택한다. 서버의 새 실행 API는 클라이언트가 이전 버전을 직접 지정해서 새 기록을 만드는 것을 계속 거부해야 한다. 이 경계 덕분에 저장된 과거 기록은 재현하면서 새 링크나 조작된 요청으로 예전 규칙의 신규 랭킹을 만들 수 없다.

공용 설정 파일에는 리듬의 현재 모드 `rhythm-three-lane-v11`과 멀리 뛰기의 현재 모드 `jump-distance-v11`, 두 모드의 한국어 표시 이름도 함께 반영했다.

## 검증

- `tests/city-v11-engine.test.mjs`: 피해, 한 겹침 한 타격, 보호 시간, 방어, 연료 종료, 0.5/s 감소, 1.5배 배치, 부스터 발동·시간, seeded replay, 바퀴 접점
- `tests/city-v11-options.test.mjs`: 8종 ID와 수치, v7 모드, 모든 구매 전 표시
- `tests/city-v11-garage.test.mjs`: 인메모리 SQLite에서 일곱 차량의 정확한 가격·원자적 구매·재구매, v7과 v6 정산 재현
- `tests/city-v11-render.test.mjs`: 직립 원화 경로, 네 교통 자산, 기하학 폴백, v7 결과 필드
- `tests/city-v6.test.mjs`: 보존한 v6 엔진 회귀
- `tests/game-options-v11.test.mjs`: 리듬·멀리 뛰기의 현재 버전과 명시적인 이전 버전 보존

검증은 사용자 데이터와 4173 서버를 사용하지 않는다. 차고 통합 테스트는 매 실행마다 `:memory:` SQLite와 임의 로컬 포트를 만들고 종료한다.

집중 검증 결과는 도시 및 공용 게임 설정 52개 테스트 통과다. 추가로 v4·v5 도심 엔진 단위 회귀 12개가 통과했으며, 남은 v4 통합 fixture 한 건은 랭킹 기본 모드 기대값을 `city-basic-v6`에서 `city-basic-v7`로 갱신하면 된다.
