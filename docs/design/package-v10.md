# 뒹굴 픽셀 디자인 패키지 · v10

[서비스](https://dwingul.com) · [전체 아트북](https://dwingul.com/artbook/)

기존 홈페이지의 숲속 친구를 유지하면서, 썸네일만 보고도 어떤 놀이인지 구분하도록 각 서비스의 도구와 행동을 새로 그렸다. 실제 플레이와 질문·결과·장비 화면도 크림 종이, 나무 테두리, 이끼색 버튼으로 연결한다.

아트북은 482개 제작 항목을 보여준다. 썸네일은 별도로 모바일용 480×320과 큰 화면/공유용 960×640을 제공한다. 실제 색상 판정·신호 색·충돌 범위와 저장된 장비 ID, 능력치, 뽑기 확률은 유지한다. 멀리 뛰기는 모바일 화면에서 장면을 확대해 캐릭터를 더 쉽게 볼 수 있도록 했다.

## 파일 위치와 재생성

- `public/assets/pixel/thumbnails/`: 서비스별 WebP, 21쌍.
- `public/assets/pixel/portraits/`: 투명 배경 캐릭터 WebP.
- `public/assets/pixel/items/`, `personas/`, `rpg/`, `world/`: 앱과 캔버스에서 직접 사용하는 SVG.
- `public/css/world.css`: 전체 서비스의 공통 내부 스타일. 기존 홈페이지 `pixel.css` 이후 로드.
- `public/js/art.js`: 썸네일/오행 연결, 크기 예약과 이미지 실패 대체 표시.
- `public/js/pixel-world.js`: 캔버스 이미지 캐시·그리기. 장식과 게임 판정 분리.
- `scripts/generate-pixel-assets.mjs`, `generate-world-assets.mjs`: SVG 제작기. 생성된 SVG만 수동 수정하면 다음 빌드에 덮어쓰므로 제작기를 수정한다.
- `scripts/build-artbook.mjs`: 실제 파일·카탈로그에서 아트북 목록 생성.

`npm run build`로 SVG, 아트북, 정적 가이드를 다시 만든다. 이미지 생성 API 호출 없이 기존 WebP를 사용하므로 협업자가 같은 결과를 재현할 수 있다.

## 제작 방법·출처

썸네일과 캐릭터 원화는 내장 **image_gen** 도구로 제작했다. 기존 뒹굴 `woodland-pets.png`를 스타일 참고로 사용했다. 경쟁 서비스의 이미지·코드는 복사하지 않았다. 정확한 프롬프트와 각 결과 파일의 대응은 다음 문서에 보관한다.

- [썸네일 프롬프트](../../design/image-prompts-v10.json)
- [캐릭터 프롬프트](../../design/portrait-prompts-v10.json)
- [사전 검토·제작 목록](../plans/2026-09-14-pixel-package-v10.md)
- [RPG 구현·검증](../plans/v10-rpg-art.md)
- [화면별 QA 기록](../plans/v10-world-qa.md)

이미지 생성 원본 PNG는 로컬 `design/masters/`에 보관하고 Git/배포에서는 제외한다. 서비스용 WebP는 저장소에 포함한다. SVG 아이콘·장비·UI는 직접 작성한 제작기로 생성한다. 글꼴은 기존 상업 이용 가능한 Galmuri(OFL)를 유지하며 라이선스는 저장소의 글꼴 디렉터리에 포함되어 있다.

## 새 콘텐츠를 추가할 때

1. 서비스의 핵심 동작 하나를 큰 도구와 캐릭터 동작으로 표현한다. 캐릭터 얼굴만 반복하지 않는다.
2. 그림 안에 서비스 제목을 넣지 않는다. 읽을 수 있는 제목과 안내는 HTML에서 제공한다.
3. 크림 `#fff8e8`, 갈색 `#49382d`, 숲색 `#405c3e`, 이끼 `#91a877`, 금색 `#dfb665`를 기준으로 쓴다.
4. 썸네일 두 크기와 카탈로그 연결을 함께 추가한다. 큰 이미지와 복잡한 배경을 플레이 조작 영역 위에 얹지 않는다.
5. `npm test`, `npm run check`, `npm run build` 이후 격리된 로컬 서버에서 모바일/PC 화면과 실제 입력을 확인한다. 공개 서버에 테스트 기록을 만들지 않는다.
